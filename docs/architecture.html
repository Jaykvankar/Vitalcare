Vitalcare: how it is built and how a hospital uses it

Remote patient monitoring where every vital sign is encrypted on the device, scored by rules and an AI model on arrival, stored under a key that belongs to that one patient, and opened only for the care team the patient has consented to.

What data the project uses

The live AI model learns from synthetic data because no open dataset marks the minute a patient started to deteriorate. Three real, de-identified datasets are used to test the system honestly and to replay real patients through the encrypted pipeline.

Real data across many hospitals

eICU: does it work at hospitals it has never seen?

The eICU demo is now part of the project. Its stays come from 186 different hospitals and record vitals every 5 minutes, close to how a wearable reports. That lets us test the question every new hospital will ask: does a model built elsewhere work here?

  • On real multi-hospital data, NEWS2 beats the synthetic-trained model. The synthetic model only came out ahead on the small MIMIC set.
  • A simple model trained on real data from other hospitals does best on hospitals it never saw. Retraining on real data is the clear next step.
  • At 5-minute resolution there are 3.8 critical alerts per patient-day in these ICU patients: too many for a ward without tuning (alarm fatigue).
  • Temperature was charted for only 157 of the 2,048 stays. Elsewhere it is held at 36.9 °C, so fever rules cannot fire for those patients.

Full numbers, including results by region and teaching status: docs/real_data_report.md (regenerate with python -m app.ml.eval_real).

About "big data" and BigQuery

Once a PhysioNet account is approved for credentialed data, the full eICU and MIMIC-IV can be queried in Google BigQuery, so only the needed vital-sign rows are exported instead of downloading tens of GB. Credentialing is personal (CITI "Data or Specimens Only Research" course plus a signed data use agreement). That data must never be shared or committed; .gitignore already excludes data/real/.

Try it

Run the working demo

One command takes a fresh checkout to a running system with four monitored patients. Two replay real eICU stays from different hospitals, one replays a MIMIC-III stay, and one is synthetic so you can inject a deterioration on demand.

.venv\Scripts\python demo.py            # http://localhost:8000, monitors start streaming
.venv\Scripts\python scripts\totp_code.py dr.mehta   # 6-digit code for staff sign-in

Five-minute walkthrough

  • dr.mehta: the worklist is ranked by urgency. Open the top patient to see the AI explanation, trends and alerts. Acknowledge one with a note.
  • admin: Data sources lets you switch a monitor to another real ICU stay or inject a hypoxia episode. Bulk import onboards staff from a CSV. The privacy ledger verifies itself.
  • p.iyer: sees only her own data, can pause sharing and download everything held about her.
